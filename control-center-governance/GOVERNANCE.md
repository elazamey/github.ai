# Governance Policy

## الغرض

تحدد هذه الوثيقة الحد الأدنى المطلوب لإدارة المشاريع عبر مركز التحكم. الغاية هي جعل حالة المشروع والانتقال بين المراحل قابلة لإعادة الفحص، مع فصل واضح بين التوثيق والنتيجة التنفيذية.

## قواعد إلزامية

| القاعدة | التطبيق |
|---|---|
| Evidence مرتبط بـSHA | كل نتيجة يجب أن تشير إلى commit محدد وفرع ووقت تنفيذ |
| لا نجاح ضمني | `NOT_RUN` وغياب النتيجة لا يساويان `PASS` |
| مراجعة Read-Only | المراجع الآلي يحلل ويكتب تقريرًا فقط ولا يعدّل مصدر المشروع |
| الاستثناء موثق | أي تجاوز لشروط Gate يحتاج قرارًا في `DECISIONS/` |
| Checkpoint غير كافٍ وحده | الـbaseline لا يحل محل الاختبارات أو Evidence التنفيذي |
| حماية الفرع تدريجية | تُجهّز القواعد وتُختبر قبل تفعيلها على فرع رئيسي فعلي |

## انتقال Gate

لا ينتقل المشروع إلى Gate لاحق إلا إذا كان Gate الحالي في حالة `PASS`، وكانت كل الشروط المطلوبة معرفة في `GATES/gates.json`، وكانت تقارير Evidence متاحة للمراجعة. عند وجود نقص، يكون القرار `BLOCK` مع توضيح السبب والإجراء المطلوب.

## حدود هذه النسخة

لا تُفعّل هذه النسخة حماية فرع خارج مركز التحكم تلقائيًا، ولا تفترض وجود أوامر بناء أو اختبار في مشروع مسجل. يجب تعبئة ملف المشروع أولًا قبل اعتبار أي فحص خاص به صالحًا للتقييم.
