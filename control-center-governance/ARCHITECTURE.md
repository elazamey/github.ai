# Architecture

## الهدف

يعمل **Engineering Control Center** كطبقة حوكمة مستقلة فوق مستودعات المشاريع. لا يستبدل مستودع التطبيق ولا يكتب إلى مصدره؛ بل يحتفظ بتعريف المراحل، معايير القبول، الأدلة، والقرارات التي تسمح بالمراجعة وإعادة الإنتاج.

## المكونات

| الطبقة | المسؤولية | المدخلات | المخرجات |
|---|---|---|---|
| Source | commits وbranches وtags في مشروع العمل | تغييرات الكود | SHA قابل للتتبع |
| Actions | تشغيل الفحوصات عند Push/PR | SHA وبيئة CI | نتائج checks |
| Gate Engine | مقارنة النتائج بشروط Gate | checks وملف Gate | PASS أو BLOCK |
| Evidence | حفظ سياق التنفيذ | SHA والنتائج والبيئة | تقرير Markdown |
| Governance | القرارات والـbaselines | Evidence وقرارات المراجعة | سجل قابل للتدقيق |

## تدفق القرار

1. يحدد ملف Gate شروط القبول بوضوح.
2. تنفذ Actions أو الأدوات المحلية الفحوصات على SHA محدد.
3. يجمع مولّد Evidence النتائج والسياق التشغيلي.
4. تراجع النتيجة مقابل شروط Gate.
5. يُسجل القرار، ولا يُسمح بالانتقال عند وجود شرط `BLOCK`.

## حدود الإصدار الأول

الإصدار الأول لا يدّعي تنفيذ اختبارات مشروع خارجي أو إدارة صلاحيات GitHub تلقائيًا. يركز على الهيكل، التوثيق، والتحقق من اكتمال تعريف الـGates، مع نقطة توسعة واضحة لإضافة فحوصات خاصة بكل مشروع.

## مبدأ Read-Only

أي مراجع آلي مستقبلي، بما في ذلك AI Project Auditor، يجب أن يعمل بصلاحية قراءة وتحليل فقط. لا يجوز له تعديل كود المشروع أو إغلاق/دمج Pull Request أو تجاوز شروط Gate.
